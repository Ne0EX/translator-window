# Reader feedback for v0.2.0

Recorded: 2026-09-25. Baseline: the v0.1.0 reading workflow and supplied screenshots.
Exact build, zoom, and session state are not recorded for every image.

## Reader priorities

1. Current performance is good enough for this reader. Preserve that experience;
   further general speed optimization is secondary to presentation.
2. Local model VRAM use and warmup limit accessibility. Investigate an optional
   free or inexpensive translation API for future distribution. The reader chose
   reader-supplied API keys for the first prototype.
3. Improve automatic placement and font sizing first, especially overflow and
   slight positional offsets.
4. Target color-page presentation and custom font styling for v0.2.0. The supplied
   generated image is the direction for readable, integrated typesetting.

This acceptance updates the priority of PROB-001, not its historical measurements
or claims about other machines. PROB-002/003 startup and resource limits remain.

## Evidence rules

- The 15 JPEGs contain 14 unique files: EX14 and EX15 are byte-identical. Two
  additional PNGs provide a Google comparison and a generated target.
- Files stay on the reader's machine. This record identifies inputs without
  redistributing photos, artwork, browser tabs, or screenshots.
- Camera angle, scaling, and moiré prevent pixel-accurate offset, clipping, color,
  or contrast measurements from the photos.
- Static images cannot establish responsiveness, caption age, pipeline stage,
  missing detection, or translation fidelity without an original and session data.
- Some images appear to show earlier builds. Replay against the frozen baseline
  before counting an already repaired chart problem as an active regression.
- The generated target is a composition/style reference, not an authoritative
  translation, original image, or demonstration of runtime speed.

### Color original and concrete visual target

The reader supplied the [reader page](https://raw.senmanga.com/%E3%82%B6%E3%83%A9%E3%83%A1%E3%81%AA%E6%81%8B%E3%81%AF%E7%94%98%E3%81%8F%E3%81%AA%E3%81%84%E3%80%80%E8%AA%AD%E5%88%87/1.3)
and [direct image](https://cdn.uqni.net/users/449/2026/09/20-731535.webp).
The direct image was downloaded to ignored local evidence and inspected; the
reader page itself could not be opened by the web text tool. These links identify
the submitted evidence, not permission to redistribute it.

SRC01 confirms distinct visual roles: ordinary dialogue in white balloons,
red/yellow/white promotional lettering with glow on colored artwork, and blue/red
emphasis inside dialogue. The top, center and bottom headlines need their visual
hierarchy preserved; the center/lower covers in EX08/11 flatten these treatments.
Balloon borders, faces, hair, star decorations, and unaffected artwork are protected
content. Redrawing entire rectangular banners is not sufficient preservation.

The middle-left original contains a complete assertion about nothing being
impossible, while EX08 shows a much shorter caption. That is a text completeness
case as well as a presentation case; OCR and translation outputs are needed to
attribute the loss. Generated reference wording does not settle that attribution.

## What the current code establishes

- `SubtitleOverlay.RenderCore` anchors size/placement to padding-expanded masks,
  starts font candidates from source height, searches a small set of widths, and
  accepts the first successful placement. `SubtitleLayout.Place` uses a monitor
  boundary plus candidate checks; there is no explicit balloon/panel ownership
  model. These are investigation targets, not proven causes for each photo.
- The preferred Japanese-to-Thai path filters sizes below 12 DIP, but its final
  relaxed fallback can bypass that filter. A universal 12-DIP guarantee is not
  established by the current code.
- `MaskBrush` fills rectangles from nearby colors; `BackgroundBrush` favors flat
  areas. Foreground is black/white with fixed regular typefaces. Color images can
  be processed, but faithful reconstruction and source-style typography are missing.
- `ThaiWords` depends on Windows segmentation. PROB-010's hosted CI failure must
  be resolved before cross-machine wrapping can be called qualified.

## Inputs needed for implementation acceptance

For each selected case, retain a local original captured frame and translated
render at the same viewport, plus app commit, languages, capture mode/bounds,
DPI, zoom, region text/bounds, caption bounds/font/line breaks, and fallback reason.
Capture data remains opt-in and local.

Select one failing case per priority category and EX14 as a passing control.
Cover monochrome dialogue, a dense page, chart labels, a plain color balloon, a
color banner, and stylized lettering. Annotate intended text containers and
protected artwork independently of detector output.

SRC01 now supplies the color original. Exact viewport captures and stage outputs
are still needed to reproduce offsets and attribute text loss; the photographed
translation and original image have different scales and crops.
