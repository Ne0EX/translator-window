# v0.2.0 plan: readable manga layout, color typography, and API feasibility

Status: proposed implementation plan, based on reader feedback on 2026-09-25.
Published tracking issue: [#1](https://github.com/Ne0EX/translator-window/issues/1).
This document preserves the planning baseline; use the issue for current progress.
Planning work only; the app version and published v0.1.0 assets are unchanged.

## Outcome and priorities

The reader now considers performance good enough for reading. Preserve that
interaction baseline and prioritize caption fit, positioning, and font sizing.
The v0.2.0 visual target is Thai typesetting that belongs in the manga: balanced
speech captions, preserved panel/balloon edges and artwork, and appropriate banner
emphasis on supported color pages.

VRAM and cold warmup remain accessibility problems. Evaluate optional remote
translation in parallel; it is not a prerequisite for correcting local layout.

Evidence: [screenshot inventory](../feedback/2026-09-25-v0.2.0.md),
[domain glossary](../../CONTEXT.md),
[problem/decision ledger](../project-ledger.md),
and [API research](../research/translation-api-options.md).

The 15 JPEGs contain 14 unique photos; two PNGs are comparison/target references.
Images remain local. EX04/06 and EX05/07 are related views, and EX14/15 are exact
duplicates. Some chart photos likely predate existing fixes. Static photos do not
prove a detector fault, mistranslation, dynamic lag, or exact pixel offset.

## Release scope

| Track | Intended v0.2.0 outcome | Boundary |
| --- | --- | --- |
| Layout and font sizing | Contained, readable, consistently aligned Thai captions and coherent margin fallback | Core release requirement; preserve all translated text rather than shorten it to fit |
| Color presentation | Qualified plain/gradient color balloons and banners; fewer broad rectangular covers; dialogue/narration/emphasis style controls | Core on a declared support matrix; complex lettering over detailed artwork requires its own successful feasibility gate |
| Stylized source text | Diagnose missing headings separately from layout; qualify a finite supported sample | Improvements depend on replayed detection/recognition evidence; layout does not recover missing text |
| API translation | Measure quality, cost, warmup, memory and latency with one official text API | Reader-supplied keys confirmed; optional preview only if its gates pass; provider not selected yet |

The generated reference defines visual qualities, not a verified translation or
an exact font/art reconstruction requirement. Full-page image generation is not
the proposed runtime path. It would require separate evidence for content fidelity,
latency, cost and privacy.

## Ordered work

### 1. Establish reproducible layout inputs and a working Thai gate

- [ ] Select original captured frames for EX03, EX05/07, EX08/11, EX09, EX10/13,
  the recovered charts, and EX14 as a passing control. Include EX12 for coverage.
- [ ] Save local-only frame plus region/translation/layout data, capture target,
  DPI/zoom, version, font and fallback reason. Annotate intended text containers
  and protected artwork independently of detector output.
- [ ] Replay with fixed recognized text and translations to isolate presentation;
  separately exercise the complete detector/recognizer/translator path.
- [ ] Resolve PROB-010 by comparing Windows Thai tokens, installed language
  capabilities and wrap results. Qualify an explicit prerequisite or a consistent
  segmentation path; retain the failing assertion and run the later CI checks.

Exit: at least one deterministic failing reproduction per selected defect class,
a passing sparse-page control, and green Thai/overlay/layout CI on a fresh runner.
The reader supplied the 960 × 1365 color original as SRC01; its URL, hash and
inspection findings are in the evidence record. Exact viewport/stage replays
remain necessary for the photographed defects.

### 2. Correct anchors, containment and dense placement

- [ ] Distinguish source text bounds, cover padding, and the text container.
  Investigate the current `source = masks[i]` coupling before changing it.
- [ ] Constrain overwrite captions to an associated container or an explicitly
  permitted local area. Respect capture boundaries, panel edges, faces, chart
  connectors and adjacent captions. Use numbered margins when local fit fails.
- [ ] Keep caption/badge associations one-to-one and inside the selected reading
  area. Avoid unrelated browser controls, off-screen lists and orphan badges.
- [ ] Move captions with their source while preserving relative layout; recompute
  wrapping/sizing only when scale, text, style or available space changes. Keep
  current cancellation/source checks.

Start with bounded corrections to `SubtitleOverlay` and `SubtitleLayout`. Reuse
existing placement, proof and margin paths. Add container detection only where
the replay demonstrates that existing evidence is insufficient; do not begin by
adding an always-resident segmentation model or a new rendering framework.

Exit: zero clipped captions, unauthorized panel/artwork intersections, caption
collisions, or lost associations on the qualified set. Under a pure translated
view at unchanged scale, font and line breaks are stable and residual placement
drift is at most 2 physical pixels (proposed fixture tolerance, not a photo claim).

### 3. Choose font size, line breaks and width together

- [ ] Evaluate valid font/width/position candidates together instead of relying
  on source-text height as the font ceiling and accepting the first fit.
- [ ] Select a readable result consistent with its dialogue/narration/emphasis
  role; then maximize size within that role and container. Preserve Thai words,
  grapheme clusters, punctuation, names, numbers and the full translation.
- [ ] Apply a 12-DIP minimum to every normal Thai reading fallback. If nothing
  fits, use a readable margin or leave source visible with the existing fit-failure
  status message.
  Close the current relaxed fallback that can bypass the preferred floor.
- [ ] Cache measurements/layout with relevant text, font, style, scale and
  container inputs so new sizing work does not repeatedly block navigation.

Exit: no clipping, detached Thai marks, silent truncation or unreadably small
fallback. A larger candidate may be rejected only for recorded fit/style reasons.
Sparse successful captions stay local; dense pages improve without hiding text.

### 4. Preserve color backgrounds and introduce caption styles

- [ ] Separate the source-text footprint from its rectangular region/container.
  First qualify plain fills and gradients using existing image-processing tools.
- [ ] Limit reconstruction to the permitted lettering/effect area. Preserve
  balloon outlines, panel borders, faces and artwork outside that area exactly in
  fixture comparisons. The appearance behind lettering is inferred, not recovered
  ground truth.
- [ ] Add a small set of dialogue, narration and emphasis styles, with controls
  for Thai-capable typeface, weight, foreground color and outline/shadow. Preserve
  horizontal Thai reading and headline/body hierarchy from the target reference.
- [ ] Use source color/weight cues where reliable and allow explicit overrides.
  Validate glyph coverage and font redistribution rights before bundling fonts.
- [ ] Preserve inline emphasis only when the corresponding translated phrase is
  known or explicitly selected. Japanese glyph positions do not directly identify
  which Thai words should become blue/red; retain a readable style when uncertain.
- [ ] Probe detailed artwork/large stylized lettering separately. If reconstruction
  cannot preserve artwork within the memory/latency budget, keep source visible
  and use a readable caption fallback; document the unsupported class.
- [ ] Audit EX12 intended text against detection/recognition output before
  selecting any detector/OCR change. Do not treat every unoverwritten glyph as
  proof of a detection miss.

Exit: paired original/result review for a plain colored balloon, a gradient
banner and an emphasized heading. All glyphs fit and remain legible; foreground,
outline and background work together at normal viewing size. The EX08/11 broad
cover artifacts are absent for qualified cases. No claim of general color-page
support without the corresponding source-preservation evidence.

### 5. Evaluate one optional translation API

- [ ] Choose one official provider after the dated research. The reader confirmed
  reader-supplied keys for the first prototype: protect credentials locally and
  exclude them from logs/settings exports; no embedded shared credential or
  project-funded backend. Azure Translator F0 is the initial evaluation candidate,
  with Google NMT and a low-cost LLM as conditional comparators.
- [ ] Retain capture, OCR and layout locally. Send only selected recognized text
  and explicit minimal context after the reader selects remote translation.
  Screenshots, full desktop data and browser chrome are outside this prototype.
- [ ] Avoid loading the local translation model in remote mode. Measure remaining
  OCR warmup/VRAM separately; a text API cannot eliminate those costs.
- [ ] Preserve bounded progressive region results, source/target language, region
  association, duplicate suppression and stale-result rejection. Render completed
  caption units; network arrival must not move existing captions unexpectedly.
- [ ] Bound retries and concurrency; handle timeout, 429, quota exhaustion and
  offline conditions explicitly. Cancellation may not cancel provider billing.
  Keep original source visible; local-model fallback requires the reader's choice.
- [ ] Measure billed characters/tokens, cost per 100 pages, request counts, p50/p95
  first-caption/completion delay, host/VRAM use, and human-reviewed Thai meaning.
  Include context/prompt overhead and retries in the cost calculation.

Exit: reproducible results on the protected name/relationship/negation/number
corpus, costs within a stated reader budget, documented provider data treatment,
and no content transmission before mode selection. A free quota is not an
unlimited free service. No provider or speed/quality claim is approved by this plan.

## Release qualification

- [ ] Local and hosted checks pass on the exact candidate commit, including the
  currently failing Thai gate. Publish only after those results are available.
- [ ] Test ordinary text, monochrome dialogue, dense charts, the qualified color
  cases, and the sparse negative control at supported DPI/zoom settings.
- [ ] Recheck progressive arrival, scrolling, paper-like page turns, minimize,
  Stop, stale-result rejection and caption restoration in the live reader.
- [ ] Preserve the user's accepted experience on matched machine/workload runs.
  Proposed regression budget: no more than 10% deterioration in warm p50/p95
  first-caption/completion times; record host/VRAM peaks and source stutter too.
  Treat small timing differences within repeat-run noise as inconclusive.
- [ ] No new always-resident GPU model in the core layout/style path without a
  measured budget decision. Any expensive reconstruction path must be bounded,
  cancellable and separately qualified.
- [ ] Validate fresh-machine setup, fonts/Thai segmentation, and any API-key setup.
  Scope physical mixed-monitor acceptance honestly if hardware remains unavailable.
- [ ] Reader reviews the supported color cases against the visual target.
  Human-quality translation remains a separate review axis, never inferred from
  beautiful typesetting or successful API responses.
- [ ] Record support matrix, remaining defects, dependency/font notices, costs,
  privacy mode, verification evidence and migration notes. Then cut immutable
  v0.2.0 artifacts and checksums; do not rewrite v0.1.0.
