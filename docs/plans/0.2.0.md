## Outcome and priorities

The reader now considers performance good enough for reading. Preserve that
interaction baseline and prioritize caption fit, positioning, and font sizing.
The v0.2.0 visual target is Thai typesetting that belongs in the manga: balanced
speech captions, preserved panel/balloon edges and artwork, and appropriate banner
emphasis on supported color pages.

VRAM and cold warmup remain accessibility problems. Remote translation is deferred
to independent API backlog issues #14–#18 and is not part of v0.2.0.

### 2. Correct anchors, containment and dense placement

- [ ] Distinguish source text bounds, cover padding, and the text container.
  Investigate the current `source = masks[i]` coupling before changing it.
- [ ] Constrain overwrite captions to an associated container or an explicitly
  permitted local area. Respect capture boundaries, panel edges, faces, chart
  connectors and adjacent captions. Use numbered margins when local fit fails.
- [ ] Keep caption/badge associations one-to-one and inside the selected reading
  area. Avoid unrelated browser controls, off-screen lists and orphan badges.
- [ ] Move captions with their source while preserving relative layout; recompute
  wrapping/sizing only when scale, text, style or available space changes. Keep
  current cancellation/source checks.

Start with bounded corrections to `SubtitleOverlay` and `SubtitleLayout`. Reuse
existing placement, proof and margin paths. Add container detection only where
the replay demonstrates that existing evidence is insufficient; do not begin by
adding an always-resident segmentation model or a new rendering framework.

Exit: zero clipped captions, unauthorized panel/artwork intersections, caption
collisions, or lost associations on the qualified set. Under a pure translated
view at unchanged scale, font and line breaks are stable and residual placement
drift is at most 2 physical pixels (proposed fixture tolerance, not a photo claim).

### 3. Choose font size, line breaks and width together

- [ ] Evaluate valid font/width/position candidates together instead of relying
  on source-text height as the font ceiling and accepting the first fit.
- [ ] Select a readable result consistent with its dialogue/narration/emphasis
  role; then maximize size within that role and container. Preserve Thai words,
  grapheme clusters, punctuation, names, numbers and the full translation.
- [ ] Apply a 12-DIP minimum to every normal Thai reading fallback. If nothing
  fits, use a readable margin or leave source visible with the existing fit-failure
  status message.
  Close the current relaxed fallback that can bypass the preferred floor.
- [ ] Cache measurements/layout with relevant text, font, style, scale and
  container inputs so new sizing work does not repeatedly block navigation.

Exit: no clipping, detached Thai marks, silent truncation or unreadably small
fallback. A larger candidate may be rejected only for recorded fit/style reasons.
Sparse successful captions stay local; dense pages improve without hiding text.

### 4. Preserve color backgrounds and introduce caption styles

- [ ] Separate the source-text footprint from its rectangular region/container.
  First qualify plain fills and gradients using existing image-processing tools.
- [ ] Limit reconstruction to the permitted lettering/effect area. Preserve
  balloon outlines, panel borders, faces and artwork outside that area exactly in
  fixture comparisons. The appearance behind lettering is inferred, not recovered
  ground truth.
- [ ] Add a small set of dialogue, narration and emphasis styles, with controls
  for Thai-capable typeface, weight, foreground color and outline/shadow. Preserve
  horizontal Thai reading and headline/body hierarchy from the target reference.
- [ ] Use source color/weight cues where reliable and allow explicit overrides.
  Validate glyph coverage and font redistribution rights before bundling fonts.
- [ ] Preserve inline emphasis only when the corresponding translated phrase is
  known or explicitly selected. Japanese glyph positions do not directly identify
  which Thai words should become blue/red; retain a readable style when uncertain.
- [ ] Probe detailed artwork/large stylized lettering separately. If reconstruction
  cannot preserve artwork within the memory/latency budget, keep source visible
  and use a readable caption fallback; document the unsupported class.
- [ ] Audit EX12 intended text against detection/recognition output before
  selecting any detector/OCR change. Do not treat every unoverwritten glyph as
  proof of a detection miss.

Exit: paired original/result review for a plain colored balloon, a gradient
banner and an emphasized heading. All glyphs fit and remain legible; foreground,
outline and background work together at normal viewing size. The EX08/11 broad
cover artifacts are absent for qualified cases. No claim of general color-page
support without the corresponding source-preservation evidence.

## Deferred remote translation backlog

Remote translation is outside the v0.2.0 release and has no dependency path into
issue #13. The provider-neutral BYOK work is separated into:

- [#14: BYOK support for translation services and LLM providers](https://github.com/Ne0EX/translator-window/issues/14)
- [#15: qualify and select the first BYOK provider](https://github.com/Ne0EX/translator-window/issues/15)
- [#16: introduce a provider-neutral session boundary with local parity](https://github.com/Ne0EX/translator-window/issues/16)
- [#17: deliver the first explicit BYOK reading integration](https://github.com/Ne0EX/translator-window/issues/17)
- [#18: qualify remote reading and further-provider compatibility](https://github.com/Ne0EX/translator-window/issues/18)

These issues cover both translation services such as Google and Microsoft and
LLM providers such as Qwen, Tencent, OpenAI, and Gemini. This candidate contains
no provider selection, API client, credential storage, remote content transfer,
cost claim, or API-key setup gate.
