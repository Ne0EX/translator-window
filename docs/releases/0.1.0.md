# Translumo Local 0.1.0

Released: 2026-09-25

Translumo Local 0.1.0 is the first source release of the local Windows manga translation workflow developed in this repository. It is intended for technically comfortable Windows users who can run the setup script, keep the downloaded models with the checkout, and review machine translations rather than treat them as authoritative editions.

This is a source release. It is not a standalone installer or a portable single-file application.

The GitHub release is marked as a **prerelease**. Human translation quality, smoothness in native animated readers, and setup on a clean Windows machine still require broader validation. The repository checks described below verify the current development system and saved fixtures; they are not a fresh-machine installation certification.

## Highlights

- Captures a selected window, screen, or rectangle and overlays translated captions without modifying the source application.
- Runs OCR and translation locally after setup. The application communicates with its workers through process pipes and named memory maps; the translation worker calls its native server over authenticated loopback.
- Supports Japanese, Korean, English, and Thai OCR, with Japanese-to-Thai manga translation as the best-qualified workflow.
- Publishes recognized and translated regions progressively in bounded batches, so early captions can appear before the whole page completes.
- Hides captions during page motion and restores reusable captions only after fresh captures and source-region checks prove that they still match.
- Uses a Windows Desktop Duplication capture path when the display configuration is supported, with a GDI fallback.
- Adds a narrowly gated family-chart recovery pass for thin ruled vertical Japanese charts. It separates the nine labels on preview page 10 and ten labels on page 21 while preserving connector lines.
- Handles narrow and unreadable regions conservatively: readable overflow can move into numbered margins, while unreadable source remains uncovered and is counted in the session status.

## How it works

1. The WPF controller captures the requested desktop rectangle through a reusable capture session.
2. The frame is fingerprinted and compared with the prior frame to suppress unchanged work and detect motion.
3. The Python OCR worker receives raw BGRA pixels through a named memory map. Comic Text Detector finds candidate regions, and MangaOCR recognizes Japanese text in batches.
4. Manga-specific reconciliation runs before progress is published. This includes cached-region reuse, the existing vertical-column fallback, and the new connector-gated family-chart label split.
5. The Python translation worker sends up to four texts at a time to a pinned local `llama-server`. Indexed progress is validated against the final response.
6. The overlay places captions around the original text masks, reuses stable layout results, and moves overflow into numbered margins when necessary.

Cancellation and page-version checks cover the worker protocol and queued UI callbacks. Stale OCR or translation results are drained but are not rendered onto a newer page.

The native translation worker uses four slots, 2,048 context tokens per slot, flash attention, Q8_0 K/V cache, continuous batching, and 128/64 batch and microbatch sizes. Prompt-state caching is disabled because the worker already caches successful completed translations and does not reuse prompt prefixes.

Windows OCR and Tesseract language data provide secondary recognition paths for English, Japanese, vertical Japanese, Korean, and Thai. ## Setup and run

### Requirements

- Windows 10 version 2004 or later, or Windows 11, on x64 hardware
- Python 3.12
- Microsoft Visual C++ Redistributable
- Several gigabytes of disk space for the pinned models and native runtimes

An NVIDIA CUDA-capable GPU is the qualified fast path. Development and acceptance testing used an RTX 3060 Laptop GPU with 6 GB of VRAM. CPU fallback exists but is substantially slower. Lower-memory GPUs and other CUDA configurations have not received the same coverage.

From the repository root, run:

```powershell
.\scripts\setup.ps1 -Cuda
& '.\Start Translator.cmd'
```

Use `.\scripts\setup.ps1` without `-Cuda` for CPU-oriented setup. Setup downloads and verifies the pinned dependencies and model artifacts. Once setup is complete, recognition and translation run offline. Keep the checkout, its `.tools` directory, and the downloaded model directories together.

The setup and model attribution details are documented in the [main README](../../README.md) and [native runtime attribution](../../local-model/attribution/NATIVE-RUNTIME.md).

## Verification summary

The release was checked with focused protocol, lifecycle, pixel, OCR, translation, and layout fixtures. The figures below are deliberately narrow measurements, not end-to-end promises for every reader or machine.

| Area | Verified result |
| --- | --- |
| Desktop capture | The FP16 Desktop Duplication path reproduced the 4K fixture pixels exactly. In its representative capture-only trial, the LUT conversion path took about 44.7 ms per frame versus 63.6–65.2 ms for GDI. |
| Motion comparison | Caching bitmap dimensions reduced a full identical-4K comparison from 238–278 ms to 14.7–14.8 ms. A saved real page-change comparison fell from 21.1 ms to about 1.4 ms. |
| OCR transport | For a 3840×2088 fixture, named-memory-map transport reduced the measured encode/copy/open/decode path from about 351 ms to 47 ms. Detector and recognition time were excluded. |
| Detector | Removing unused graph heads reduced median CPU detection across 27 saved pages from about 1,283 ms to 282 ms with exact block tensors and boxes. |
| Region fingerprints | Incremental row hashing reduced the measured allocation for the dense fixture from about 3.29 MB to roughly 2.2–2.3 KB. |
| Translation memory | Q8_0 K/V cache reduced the four-slot KV allocation from 512 MiB to 272 MiB and reduced the native dedicated-memory peak by about 224–226 MiB in the paired qualification. |
| Prompt cache | Disabling unused server prompt-state caching saved roughly 90 MiB of native private commit after the dense repeated workload. |
| Thai measurement | Replacing repeated `TextBlock.Measure` calls in wrapping with equivalent `FormattedText` measurement reduced the same-work mean from about 1,526.5 ms to 923.2 ms in the focused probe. Exact wrap decisions passed the frozen oracle cases. |
| Family charts | Across all 27 saved pages resized to 0.75×, 1×, and 1.25×, only pages 10 and 21 changed, recovering 9 and 10 chart labels. Fixed-viewport checks additionally covered pages 10, 12, 14, and 21 at 0.75× and 1.25×. Direct helper medians were about 122.5 ms and 107.2 ms on the chart pages and 49.4 ms on an ordinary control page. |

The family-chart release check rendered all 30 final page-10 regions and all 24 final page-21 regions. The connector lines remained visible, and the prior single giant translated paragraph was absent.

The source-animation experiments used WPF rendering callbacks as a scheduling proxy. They do not measure physical Comet browser presentation rate, and this release makes no Comet FPS claim. A reliable PresentMon trace was not obtained. Smoothness still depends on the source application, desktop composition, GPU scheduling, and available physical memory.

## Constraints and known problems

### Translation fidelity

The output is machine translation. Proper names, ranks, family relationships, negation, and short isolated labels remain error-prone. The application intentionally does not ship title-specific glossaries or hard-coded name replacements.

The family-chart structural fix separates labels and preserves the diagram, but it does not solve name or title translation quality. The accepted page-10 and page-21 results still contain these known defects:

- Page 10: `白日子王` gains an unwanted Thai “Title:” prefix.
- Page 10: `木梨之軽王（死去）` loses the deceased status.
- Page 21: the generation-20 and generation-22 labels both produce the incomplete Thai phrase `รุ่นที่ยี่`.
- Proper-name transliterations and relationship wording can be inaccurate. The faster native runtime has also produced a known father-to-child → father-to-student error.

The chart recovery is deliberately limited to thin ruled vertical family charts with connector evidence. It is not a general diagram parser. Other chart arrangements can remain merged or undetected.

### Capture and presentation

- The fast Desktop Duplication path is qualified for a single unrotated output using FP16 scRGB desktop frames. Unsupported formats, rotation, mirrored outputs, or rectangles spanning outputs fall back to GDI.
- Mixed-DPI and multi-monitor layouts have limited coverage.
- The overlay redraws text masks and captions; it does not reconstruct or inpaint the artwork under the source text.
- Captions smaller than the 12-DIP readability floor are moved to a numbered margin when possible. Some very narrow or crowded layouts cannot be rendered inline.
- User testing still reports visible lag in some animated readers. Low free physical memory can cause large stalls when OCR and translation models are resident. An instrumented stress fixture reached 11 MiB available physical memory, but that fixture added its own overhead and is not a production memory baseline.
- The 450 ms navigation quiet period is provisional. Physical two-finger touchpad delivery and paper-like page-turn behavior still need manual acceptance.

### OCR and layout

- Detector and OCR errors can merge speech, ruby text, chart labels, or decorative text. The family-chart pass addresses two confirmed thin-rule layouts rather than all such failures.
- Windows OCR's vertical-column fallback targets Japanese comic contents layouts and can still misgroup unusual page designs.
- Numbered margin captions preserve readability but are a fallback presentation. Their association badges can be less natural than captions placed beside the source label.
- Unreadable regions are not translated or covered by placeholder captions. Their source text remains visible.

## Release decisions

The following choices define this release:

- **Keep Q8_0 translation weights.** Q6_K saved memory but introduced material meaning regressions, including duty/role loss and an older-brother-to-younger-brother reversal.
- **Use four native translation slots.** Bounded waves improve throughput; indexed progress and final-response validation preserve protocol consistency. Known meaning errors remain.
- **Use Q8_0 K/V cache.** It produced a material VRAM reduction and passed the protected semantic review; a smaller context was rejected after a novel negation regression.
- **Disable llama-server prompt-state caching.** Prompt-prefix reuse is disabled, so retaining server prompt states consumed memory without serving a production reuse path.
- **Keep the family-chart pass narrow.** Connector and stem evidence gates recovery. Source image pixels remain unchanged; recovered label masks exclude the connector lines in the qualified fixtures. Fewer than two recovered labels retain the detector's original region.
- **Prefer readable failure.** The overlay uses a minimum text size, numbered margins, and explicit unreadable handling instead of silently producing illegible captions.
- **Retain fallbacks.** Unsupported native capture falls back to GDI; unavailable or failed native translation falls back to the existing CPU path after the native child is closed.
- **Do not claim physical browser smoothness from callback timing.** The available animation harness observes WPF callback cadence and internal stage durations, not display presentation timestamps.
