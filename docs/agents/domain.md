# Domain docs

Layout: single-context, with root `CONTEXT.md` and `docs/adr/`.

Before exploring the codebase, read `CONTEXT.md` and ADRs relevant
to the work. If absent, proceed silently. Domain modeling creates
these documents when terms or decisions are resolved.

Use the glossary's terms when naming domain concepts. If a term
is missing, reconsider the wording or note the gap for domain modeling.

Explicitly flag proposals that contradict an existing ADR,
identifying the ADR and why the decision should be revisited.
